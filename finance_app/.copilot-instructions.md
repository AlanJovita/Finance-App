# Instruções para o GitHub Copilot

## Regras de Projeto

### ❌ NÃO Fazer (sem solicitação explícita):
- **NÃO criar arquivos .md de documentação** (README, GUIDE, DEBUG, etc.)
- **NÃO criar arquivos de teste** (_test.dart, test_*.dart)
- **NÃO adicionar logs de debug** (print statements)
- **NÃO criar exemplos ou demos** sem solicitação
- **NÃO criar arquivos de configuração** extras

### ✅ Fazer Sempre:
- Modificar apenas os arquivos solicitados
- Manter o código limpo e sem logs desnecessários
- Usar as convenções de código existentes no projeto
- Formatar código com `dart format` após edições

### 📝 Documentação:
- Apenas criar documentação quando **explicitamente solicitado**
- Preferir comentários no código em vez de arquivos separados
- Documentação deve ser em português brasileiro

### 🧪 Testes:
- Apenas criar testes quando **explicitamente solicitado**
- Não adicionar código de teste em arquivos de produção

### 🔧 Debug:
- Não adicionar prints/logs a menos que solicitado
- Usar o LoggerService existente do projeto quando necessário
- Remover todos os logs de debug após solução do problema

## Estrutura do Projeto

Este é um projeto Flutter com:
- **Estado**: Provider
- **Navegação**: Named Routes + onGenerateRoute
- **API**: HTTP REST
- **Tema**: Dark/Light mode
- **Responsivo**: responsive_framework

## Padrões de Código

### Dart/Flutter:
- Usar `const` sempre que possível
- Preferir `final` sobre `var`
- Usar named parameters para widgets
- Seguir convenções do [Effective Dart](https://dart.dev/guides/language/effective-dart)

### Organização:
```
lib/
  ├── main.dart
  ├── models/          # Classes de modelo
  ├── pages/           # Telas do app
  ├── providers/       # State management
  ├── services/        # APIs e serviços
  ├── utils/           # Utilitários e helpers
  └── widgets/         # Componentes reutilizáveis
```

## Quando Sugerir Algo:

Apenas sugerir melhorias quando:
1. Houver um problema de segurança
2. Houver um bug óbvio
3. Código violar boas práticas críticas
4. For explicitamente solicitado feedback

## Respostas:

- Ser conciso e direto ao ponto
- Explicar "o quê" e "por quê", não apenas "como"
- Fornecer exemplos de código quando relevante
- Avisar sobre breaking changes ou impactos

---

**Resumo**: Seja minimalista. Faça apenas o que foi pedido. Não crie documentação ou testes extras sem solicitação.
